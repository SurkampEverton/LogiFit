## 1. Identificação do tratamento

- **Nome do módulo:** Assistente IA universal (3 camadas help/insight/action) — copilot clínico, chat ancorado por persona, sugestão operacional, resumo de evolução, pré-preenchimento de anamnese, abertura de tickets via tool
- **Sprints que entregam:**
  - **Sprint 06** (base) — entregue 2026-05-13: schemas + RLS + classifier + redact + 7 personas + tool registry + 9 tools whitelist + 3 ai-blocked + cota + audit log + LLM via Vercel AI SDK (Gemini 2.5 Flash default) + RAG seed via filesystem
  - **Sprint 11** (futuro) — biblioteca de exercícios + prescrições + integração com Copilot
  - **Sprint 13** (futuro) — Camada 2 ampliada com cross-alert + régua
  - **Sprint 20+** (Fase 2 fisio) — Comitê IA por feature SaMD II+ + tools clínicas write
- **ADRs:** [0015](../../decisions/0015-copilot-safety-vocabulario-proibido-classificador-output.md) + [0053](../../decisions/0053-conformidade-cfm-2454-2026-ia-saude.md) + [0064](../../decisions/0064-ia-arquitetura-gemini-default-byok-rag.md) + [0073](../../decisions/0073-postura-seguranca-defesa-em-profundidade.md) + [0075](../../decisions/0075-assistente-ia-universal-tres-camadas-tool-registry.md)
- **Marco regulatório:**
  - **CFM 2.454/2026** (vigência ago/2026) — IA em medicina exige Comitê IA + supervisão humana documentada + classificação SaMD por feature
  - **LGPD art. 11 II "a"** (tutela da saúde)
  - **LGPD art. 20** — direito à revisão de decisão automatizada
  - **ANVISA RDC 657/2022 + 751/2022** — SaMD classes I-IV; LogiFit MVP é **Classe I** (apoio decisional não-diagnóstico)
- **Finalidade declarada:**
  - Apoiar profissional na tomada de decisão clínica via sumarização, busca contextual e sugestão conservadora
  - Permitir paciente acessar suas próprias informações (agenda, financeiro) via diálogo
  - Acelerar operação administrativa (recepção, admin) com tool calling sob confirmação humana explícita
- **Categorias de dado tratado:**
  - [x] **Saúde** (prontuário, evolução, exame, queixa, prescrição) — Sprint 20+ Fisio integra; **MVP Sprint 06 trata apenas dado operacional** (agenda, financeiro, members básico)
  - [x] **Identificação** (mínima — apenas member_id; PII mascarado antes de envio ao LLM)
  - [x] **Composição corporal** (futuro Sprint 12 avaliações físicas)
  - [ ] **Genética** (fora MVP — Fase 4)
  - [ ] **Biometria** (Sprint 08 facial separado, RIPD próprio)

## 2. Base legal (LGPD art. 7º + art. 11)

| Categoria | Base legal | Justificativa |
|---|---|---|
| Saúde clínica processada por IA (futuro) | art. 11 II "a" — tutela da saúde + obrigação legal CFM 2.454/2026 | IA atua como ferramenta de apoio profissional; output nunca substitui decisão humana; Camada 3 exige confirmação UI |
| Dados operacionais (agenda, financeiro) | art. 7º V — execução de contrato (SaaS) | Necessário pra `getMyAppointments`, `getMyInvoices`, `getOverdueInvoices` |
| Identificação mínima | art. 7º V — execução de contrato | Necessário pra contexto da resposta; `redactBeforeLLM` mascara PII antes do envio |
| Logging de auditoria CFM | art. 7º II — cumprimento obrigação legal (CFM 2.454/2026 exige `ai_audit_log`) | Append-only (RLS + regra 5); particionamento + retenção 1a quente + 5a cold (regra 34) — Sprint 06+ ativa partition em ai_audit_log |
| Cota mensal por plano (ADR 0066) | art. 7º V — execução de contrato | Limites por plano comercial; hard-stop em 100% mensal |

## 3. Princípios aplicados (LGPD art. 6º)

- **Finalidade explícita** — Cada chamada vinculada a `persona` + `layer` em `ai_audit_log`; tools com `description` obrigatório no `tools_registry`
- **Adequação** — Tool só aparece se `persona`/`permission`/`vertical` casam (`getAvailableTools` filtra)
- **Necessidade** — Cota mensal previne uso excessivo; `redactBeforeLLM` aplicado antes do envio
- **Livre acesso** — Portal `/meu/alertas-ia` (Sprint 26) listará todas decisões IA envolvendo paciente
- **Qualidade dos dados** — Cache semântico tem TTL 30d; documentos RAG marcam `content_hash` (Sprint 06+ re-ingere quando muda)
- **Transparência** — Disclaimer fixo "sugestão auxiliar — profissional humano decide" no rodapé do AssistantSheet
- **Segurança** — Defense-in-depth (classifier I/O + redact + RLS + envelope crypto + anti-abuse + audit)
- **Prevenção** — `classifyOutput` bloqueia prescrição/diagnóstico em **toda** resposta antes de mostrar ao user
- **Não-discriminação** — Tools de Camada 3 exigem `<ActionConfirmDialog>`; nenhum efeito sem confirmação humana explícita
- **Responsabilização** — `assistant_action_proposals` + `ai_audit_log` + `audit_log` registram cada turn + decisão

## 4. Fluxo de dados (entregue Sprint 06)

```
[Profissional/Member] → AssistantFAB → /api/ai/chat
                                              │
                                              ▼ wrapServerAction (auth+RLS+rate+audit)
                                       [sendMessage]
                                              │
                  ┌───────────────────────────┼───────────────────────────┐
                  │                           │                           │
                  ▼                           ▼                           ▼
        classifyInput              redactBeforeLLM            checkQuota / checkAbuse
        (anti-injection)           (PII mascarado)            (cota plano + 10× avg)
                  │                           │                           │
                  └───────────────────────────┴───────────────────────────┘
                                              │
                                              ▼
                                  resolveModelForTask
                                  ├── BYOK ativo? decrypt key (AES-256-GCM)
                                  └── Default Gemini Vertex AI SP
                                              │
                                              ▼
                              chatComplete (Vercel AI SDK)
                              │
                              ▼ (fallback stub se sem credentials)
                       classifyOutput (prescrição/diagnóstico)
                              │
                              ▼ (Camada 3 só)
                       proposeAction → assistant_action_proposals (TTL 5min)
                              │
                              ▼ usuário confirma <ActionConfirmDialog>
                       confirmProposal → handler real (Faixa C2 valida proposal_id)
                              │
                              ▼
                       ai_audit_log INSERT (append-only, RLS, persona+layer+tokens)
                              │
                              ▼
                       bumpUsage + system_alerts (se 10× média 7d)
```

- **Origem dos dados:**
  - User input (texto livre — passa classifier + redact)
  - Contexto de rota (route+memberId quando em /app/members/[id])
  - RAG global (ADRs/Sprints/regulações curadas — `tenant_id IS NULL`)
  - Tenant docs (uploads em /app/settings/ia/knowledge — futuro)
  - Tool calls retornam dados do próprio tenant via RLS
- **Quem acessa:**
  - User que iniciou a sessão (`assistant_sessions.user_id = auth.uid()` via RLS)
  - Admin tenant via `/app/super-admin/ai-usage` (dashboard agregado, sem conteúdo bruto)
  - DPO LogiFit via `audit_log` + `ai_audit_log` (auditoria por demanda)
- **Cross-border:**
  - **Gemini 2.5 Flash** — Google Cloud Vertex AI **São Paulo** (Brasil ✅)
  - **BYOK Anthropic** — Anthropic API (US — DPA assinada; declarado em sub-processors.md)
  - **BYOK OpenAI** — OpenAI API (US — DPA; sub-processor)
  - **BYOK Groq Whisper** — Groq API (US — DPA; sub-processor)
  - **BYOK Maritaca Sabiá** — Brasil ✅ (data residency BR)
- **Retenção:**
  - `ai_audit_log`: 1 ano quente + 5 anos cold storage Parquet zstd (regra 34 + CFM 2.454/2026 art. 6º exige histórico)
  - `assistant_messages`: 90 dias quente; conversas arquivadas após 30 dias inativas
  - `ai_semantic_cache`: 30 dias TTL (auto-expira)
  - `assistant_action_proposals`: 1 ano quente + 5 cold (auditoria de Camada 3)
  - `ai_documents` / `ai_document_chunks`: indefinido (atualização via `content_hash`)
- **Anonimização** (pós-1 ano): pesquisa interna LogiFit consome `ai_audit_log` cold com `prompt_hash` em vez de conteúdo; member_id hashed

## 7. Direitos do titular (LGPD art. 18 + art. 20)

- **Direito à revisão de decisão automatizada (art. 20)** — paciente pode solicitar via `/meu/privacidade` (Sprint 26) revisão de qualquer sugestão IA aceita por profissional sobre seu prontuário. Resposta com cópia do `ai_audit_log` + nome do profissional + decisão final. **SLA 15 dias** (LGPD art. 19).
- **Direito de oposição (art. 18 §2º)** — tenant pode desabilitar IA pra paciente específico via `member_settings.ai_disabled=true` (Sprint 06+ próximo PR). Copilot deixa de sugerir nesse contexto.
- **Acesso ao log de IA** — portal `/meu/alertas-ia` (Sprint 26) lista decisões automatizadas envolvendo dados do paciente.
- **Eliminação (art. 18 IV)** — `ai_audit_log` retenção legal CFM 2.454/2026 prevalece sobre eliminação por 5 anos; após esse prazo, anonimização preserva agregado estatístico sem PII.
- **Portabilidade (art. 18 V)** — `assistant_messages` exportável em JSON via `/meu/privacidade` (Sprint 26) cobrindo conversas do próprio paciente.

3. **`prompt_hash` populado** — coluna existe mas Server Action não computa

5. **Rate limit Redis real** — sliding window 20/min/user (depende Sprint 00 Faixa 3 Redis)
6. **Cascade fallback runtime** — tentar priority 200/300 quando primário 429/5xx
7. **Upload UI tenant docs** — scan + classifier + UI `/app/settings/ia/knowledge`
8. **`system_prompt_leak` classifier output** — detectar reprodução literal do system prompt
9. **DPA inventory atualizado** — confirmar DPA Anthropic/OpenAI/Groq antes de habilitar BYOK em prod
10. **Generative UI (Sprint 28)** — validar Zod por tool + lista fechada de componentes renderizáveis
